# 贴吧签到周报格式规格

> **文档目的**: 供 AI 复用/修改贴吧签到周报功能时的完整格式规格
> **实现载体**: `push_mail.py`(同目录, `--weekly` 模式)
> **数据来源**: `tieba-run.log`(由 `tieba_sign.py` 签到程序生成)
> **实测版本**: 2026-11-17 部署于生产服务器, 真实数据验证通过

## 0. 架构概览

```
tieba_sign.py (每日 08:05 cron)
    │ 逐吧签到, 追加写日志
    ▼
tieba-run.log
    │ 每周五 22:05 cron 触发
    ▼
push_mail.py --weekly tieba-run.log
    │ 解析日志 → 统计 → 生成三段式正文
    │ SMTP 发送(QQ邮箱, 465 SSL, 纯文本)
    ▼
邮件送达 + 发送成功后日志轮转(log → log.prev)
```

## 1. 输入: 日志行格式规格

签到程序写入的日志行, 周报解析只认以下两类:

### 1.1 每日汇总行(进入"运行总结"段)

```
[YYYY-MM-DD HH:MM:SS] 签到完成: 成功 N, 已签 N, 跳过 N, 失败 N
```

示例: `[2026-11-17 08:08:57] 签到完成: 成功 57, 已签 0, 跳过 0, 失败 0`

### 1.2 签到明细行(进入"经验统计"+"签到明细"段)

```
[YYYY-MM-DD HH:MM:SS] (i/n) [吧名] 签到成功(+N经验)   ← 新版(2026-11-17客户端档)
[YYYY-MM-DD HH:MM:SS] (i/n) [吧名] 签到成功           ← 旧版(无经验标记)
[YYYY-MM-DD HH:MM:SS] (i/n) [吧名] 跳过(未加入)
[YYYY-MM-DD HH:MM:SS] (i/n) [吧名] 失败: <原因>
[YYYY-MM-DD HH:MM:SS] (i/n) [吧名] tbs 失效, 重新获取
```

`(i/n)` 为当日签到序号/总数。经验统计只提取
`签到成功(+N经验)` 行的 `N` 值; 旧版无标记行计入天数但经验缺失。

### 1.3 解析正则(实现原样)

```python
RE_SUMMARY = re.compile(
    r"^\[([\d\- :]+)\] 签到完成: 成功 (\d+), 已签 (\d+), 跳过 (\d+), 失败 (\d+)$")

RE_DETAIL = re.compile(
    r"^\[([\d\- :]+)\] \((\d+/\d+)\) \[(.+?)\] "
    r"(签到成功(?:\(\+(\d+)经验\))?|跳过\(未加入\)|失败.*|tbs 失效.*)$")
```

## 2. 输出: 周报正文格式规格

### 2.1 总体结构

```
【贴吧签到周报】<日期范围>

一、本周运行总结
<分割线>

<汇总行们>
(空行)
本周合计: 签到成功 X 次, 失败 Y 次
(空行)(空行)
二、各吧本周经验
<分割线>

<经验行们(按总经验降序)>
(空行)
本周经验总计: N
(空行)(空行)
三、签到明细(按时间顺序)
<分割线>

<明细行们(原样, 按时间顺序)>
```

- 分割线 = 40 个 `-`
- 日期范围 = 日志中出现的所有日期取 min~max
  (如 `2026-11-13 ~ 2026-11-17`; 单日时只有一天)
- 段落之间两个空行
- 邮件为纯文本(plain, utf-8), 非 HTML

### 2.2 各吧经验行的三种格式

| 情况 | 格式 | 示例 |
|------|------|------|
| 本周经验值全相同 | `[吧名] 经验+V * 天数 = 总计` | `[clannad] 经验+8 * 7 = 56` |
| 经验值混合(如首签+后续) | `[吧名] 经验+V1*n1 +V2*n2 = 总计` | `[gpt] 经验+6*1 +8*6 = 54` |
| 旧版日志无经验标记 | `[吧名] 签到成功 * 天数 (旧日志无经验记录)` | `[clannad] 签到成功 * 4 (旧日志无经验记录)` |

排序规则: 按本周获得总经验**降序**(无经验的排在有经验之后)。

### 2.3 空数据兜底

日志中无任何汇总行和明细行时, 正文为:
`周报周期内无任何签到日志!` + `可能定时任务未运行或早已失败, 请检查!`
(日期范围为空, 标题行退化为只有【贴吧签到周报】)

## 3. 统计逻辑要点

1. **经验数据源**: 仅 `签到成功(+N经验)` 行; 同一吧多次成功
   (如手动补跑+定时任务)按次数累计, 忠实反映实际获得经验
2. **已签的吧无成功行**: 当天已签(340011)不产生日志行 →
   某天漏签则该吧经验自动少一天, 统计忠实反映
3. **经验值格式化**: `Counter` 计数后, 单值显示乘法格式,
   多值显示加法组合(值升序)
4. **周合计行**: 成功/失败次数 = 各日汇总行数值直接求和

## 4. 运行机制

### 4.1 调用方式

```bash
# 生产(周五 22:05 cron, 发送+轮转)
python3 push_mail.py --weekly /path/tieba-run.log --subject "贴吧签到周报"

# 预览(打印正文不发送不轮转)
python3 push_mail.py --weekly /path/tieba-run.log --subject test --dry-run
```

### 4.2 日志轮转(关键机制)

- **发送成功后**: `tieba-run.log` 重命名为 `tieba-run.log.prev`
  (旧 prev 直接覆盖删除) → 每周日志独立, 文件不无限增长
- **发送失败时**: 不轮转, 未送达数据自动累积到下一期
  (下期周报会包含两周数据, 日期范围自动扩展, 不丢数据)
- 判断依据: `send()` 成功返回后才调用 `rotate_log()`

### 4.3 cron 配置(生产)

```
# 每日签到 + 凭证失效即时告警(退出码2)
5 8 * * * /opt/python/bin/python3 /opt/tieba-sign/tieba_sign.py >> /opt/tieba-sign/cron-run.log 2>&1; [ $? -eq 2 ] && /opt/python/bin/python3 /opt/tieba-sign/push_mail.py --subject "紧急: 贴吧凭证失效" --alert "BDUSS已失效, 请重新获取并更新服务器 /opt/tieba-sign/cookies 文件" >> /opt/tieba-sign/mail.log 2>&1

# 每周五 22:05 周报
5 22 * * 5 /opt/python/bin/python3 /opt/tieba-sign/push_mail.py --weekly /opt/tieba-sign/tieba-run.log --subject "贴吧签到周报" >> /opt/tieba-sign/mail.log 2>&1
```

### 4.4 凭证配置(notify.ini, gitignore)

```ini
[smtp]
host = smtp.qq.com
port = 465
user = <发件QQ邮箱>
password = <SMTP授权码>
to = <收件邮箱>
```

## 6. AI 修改指南

| 想改什么 | 动哪里 |
|---------|--------|
| 经验行格式 | `fmt_exp_line()` 函数 |
| 段落结构/顺序 | `build_weekly_body()` 函数 |
| 识别的日志行 | `RE_SUMMARY` / `RE_DETAIL` 正则 |
| 发送时间 | cron 第5个字段(周几) |
| 轮转策略 | `rotate_log()` 函数 |
| 主题文案 | cron 命令行的 `--subject` 参数 |

注意: 修改后务必 `--dry-run` 验证正文格式, 再等周五真实发送。
发送成功日志写入 `mail.log`(含时间戳与收件人)。
